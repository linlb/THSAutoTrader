# THSAutoTrader

基于同花顺（THS）客户端的自动化交易工具，采用闪电下单模式，并提供可视化交互界面与 API 接口

## 功能特性

- 🚀 支持市价买入、市价卖出操作，获取当前持仓数据
- 🔌 提供 API 接口，便于外部系统调用，实现自动化交易
- ⚖️ 完全基于用户操作模拟，无修改或破解同花顺客户端，确保合法合规
- 🖥️ 提供友好的交互界面，支持多种编程语言调用
- ⌨️ 通过键盘模拟输入，实现自动化交易流程

## 打包后文件（可直接运行）

- dist/下单辅助程序.exe
- 注意：需要下载整个 dist 目录，然后运行下单辅助程序.exe

## 技术栈

- Python 3.11
- Poetry（依赖管理）
- Flask（Web 服务）
- PyWin32（Windows 窗口控制）

## 使用指南

### 前置准备

1. 打开同花顺客户端
2. 登录交易账户
3. 进入目标个股页面
4. 配置快捷下单：
   - 买入金额锁定
   - 设置为一键买入（买入时不需要确认）

### API 调用示例

#### 下单接口

```bash
# 买入操作
http://localhost:5000/xiadan?code=600000&status=1

# 卖出操作
http://localhost:5000/xiadan?code=600000&status=2

# 买入操作（指定数量）
http://localhost:5000/xiadan?code=600000&status=1&amount=100
```

参数说明：

- `code`: 股票代码，如 600000（浦发银行）
- `status`: 交易类型，1 表示买入，2 表示卖出
- `amount`: 交易数量，可选

返回格式：

```json
{
  "status": "success",
  "message": "已发送按键 600000 ENTER 21 ENTER"
}
```

#### 下单确认接口
注意：这个接口应用于已经调用起闪电下单窗口的情况下使用该接口来操作（该接口逻辑里会自动点击刷新按钮来解决可用资金不同步问题）
闪电下单窗口打开，可以使用'/send_key?key=21+ENTER'接口调起

```bash
# 下单确认（满仓）
http://localhost:5000/confirm_order

# 下单确认（指定仓位）
http://localhost:5000/confirm_order?position=2
```

参数说明：

- `position`: 仓位参数，可选值为 1/2/3/4，不传则满仓

返回格式：

```json
{
  "status": "success",
  "message": "下单确认成功,仓位:2,可用数量:10000,下单数量:5000",
  "data": {
    "available_amount": 10000,
    "position": 2,
    "order_amount": 5000
  }
}
```

#### 获取当前挂单列表

```bash
curl http://localhost:5000/pending_orders
```

激活交易窗口后，按 `F3` 进入撤单页面，等待 0.3 秒，再按 `F5` 刷新并等待 0.3 秒，单击 `1047` 列表区域后执行复制。
接口只读取内容，不双击 `200`，不执行任何撤单操作，并与其他 GUI 接口共用互斥锁。

返回示例（表头以客户端实际复制内容为准）：

```json
{
  "status": "success",
  "data": [
    {
      "委托时间": "22:45:33",
      "证券代码": "601398",
      "证券名称": "工商银行",
      "操作": "证券买入",
      "备注": "未报(买卖)",
      "委托类型": "委托",
      "委托数量": "100",
      "成交数量": "0",
      "委托价格": "8.130",
      "成交均价": "0.000",
      "撤消数量": "0",
      "合同编号": "76",
      "交易市场": "上海Ａ股"
    }
  ]
}
```

`data` 为对象数组，每条委托以客户端原始表头为字段名。所有值保持字符串，保留股票代码、合同编号的前导零和价格小数位；忽略行尾多余制表符，不生成空字段名。表头无效或数据行列数不匹配时返回错误，不静默丢弃委托。
持仓、当日成交和挂单共用 `src/util/table_parser.py` 的表格解析；只有有效表头时返回 `[]`，空文本、重复/空字段名和列数不匹配均报错，持仓与成交不再静默跳过异常数据行。挂单调用额外要求表头包含 `证券代码`，不限制其他接口的字段名称。
本接口不修改股票筛选条件；返回 F3 页面当前显示的列表，不保证包含被筛选隐藏的委托。刷新后使用固定等待时间，慢速客户端仍需实际验证数据是否已更新。
复制前会清空系统剪贴板；文本格式暂不可用时继续轮询，约 3 秒仍未取得非空文本则返回 HTTP 500，不能将复制失败当作无挂单。
若出现复制验证码，自动复用持仓查询的 OCR：识别 `2405` 图片，填写 `2404` 输入框，并仅点击验证码区域内的确认按钮 `1`。确认后沿用持仓的 `2406` 错误控件检查：存在则尝试点击取消按钮 `2` 并返回错误，否则继续读取剪贴板，不再等待父容器关闭。识别失败或控件无法确认时返回错误，不重复提交验证码。
验证码处理成功后，重新等待约 3 秒读取文本。若只有有效表头，返回空数组 `[]`。GUI 锁繁忙时返回 HTTP 429。

若出现 GUI 抢锁超时，查看 `app.log`：日志记录等待接口、当前持锁接口、线程及持有时长。按持锁线程查找最后一条 `GUI步骤开始`，核对是否缺少对应的结束或失败日志，以定位窗口激活、复制或验证码处理中的阻塞。新增诊断只写文件，不更新 Tkinter 界面；30 秒仅为抢锁等待上限，不会强制终止正在执行的 GUI 操作。

#### 撤单接口

```bash
# 全部撤单（默认）
http://localhost:5000/cancel_all_orders

# 全部撤单（显式指定）
http://localhost:5000/cancel_all_orders?type=A

# 只撤买单
http://localhost:5000/cancel_all_orders?type=X

# 只撤卖单
http://localhost:5000/cancel_all_orders?type=C
```

参数说明：

- `type`: 撤单类型，可选
  - `A` 或不传：全部撤单
  - `X`：撤买
  - `C`：撤卖

返回格式：

```json
{
  "status": "success",
  "message": "全部撤单操作已执行",
  "data": {
    "operation": "全部撤单",
    "type": "A"
  }
}
```

#### 鼠标点击接口

```bash
# 点击指定坐标
http://localhost:5000/click?x=100&y=200
```

参数说明：

- `x`: 点击的 x 坐标（整数，必填）
- `y`: 点击的 y 坐标（整数，必填）

返回格式：

```json
{
  "status": "success",
  "message": "坐标点击成功: (100, 200)"
}
```

> 说明：调用前会自动激活同花顺窗口，再执行鼠标点击操作。

#### 模拟键盘按键接口

```bash
# 输入股票代码并回车
http://localhost:5000/send_key?key=600000+ENTER

# 闪电买入
http://localhost:5000/send_key?key=21+ENTER

# 闪电卖出
http://localhost:5000/send_key?key=23+ENTER

# 打开委托交易
http://localhost:5000/send_key?key=F12
```

> 说明：
>
> - URL 中的 `+` 号会被自动转换为空格
> - 每多一个空格，代表操作间隔增加 500ms
> - `21` 为同花顺键盘精灵的闪电买入快捷键
> - `23` 为闪电卖出快捷键
> - 支持其他键盘精灵的输入操作
> - 常用快捷键：
>   - F1: 帮助
>   - F3: 上证指数
>   - F4: 深证成指
>   - F5: 分时/K 线切换
>   - F6: 自选股
>   - F12: 交易

#### 检测下单程序进程接口

检测下单程序（xiadan.exe）进程是否正在运行（纯进程探测，不操作 GUI，不依赖窗口焦点）。

```bash
http://localhost:5000/check_trading_app
```

返回格式：

```json
{
  "status": "success",
  "running": true
}
```

说明：`running` 为 `true` 表示 xiadan.exe 进程存在，`false` 表示未运行。注意该接口仅判断进程是否存活，不代表程序已登录或下单窗口已就绪。
